# v0.10.1：照片与首章节标题独立布局

- 照片绝对定位于组合页眉，个人信息文字按实际内容高度自然排版。首个正文块为独立章节标题时，标题紧接联系方式排版，可与照片下部共享同一行区域；全宽分隔线位于组合区域底部，与照片底部至少保留 2pt，正文不与照片重叠。没有独立首标题时仍保留安全的照片占位。
- 个人信息与首章节间距滑块调整标题与文字间距，不受照片高度限制。照片大小及顶部偏移滑块仍可用；非常高的照片可能使标题与横线的间距增加。
- 适用于 AI、本地识别、旧项目以及 HTML/PDF 导出；无需重新识别。

- 03 岗位适配支持粘贴文本或图片 OCR。选择 PNG/JPG（最多 10MB、3000 万像素）并预览，点击识别后使用已保存的视觉模型配置逐字转录，保留原文换行；不确定字符标注 `[无法辨认]`。结果追加到可编辑 JD 框，不自动触发匹配；可逐张识别长截图。识别前需确认发送截图给模型服务，可能产生费用。不是本地 OCR 引擎，也无需第三套 API 密钥。

# Resume Agent v0.7 · 视觉 AI 简历识别与岗位适配

## Windows / PowerShell 启动

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python server.py
```

打开 http://127.0.0.1:8765 。如果已有虚拟环境与依赖，直接重新启动即可。服务仅绑定本机，不要未经认证暴露到公网。

## 模型设置（仅 AI 功能需要配置）

左侧栏「设置」分别配置视觉识别和 JD 改写。预设 OpenAI、DeepSeek、通义千问（阿里云百炼）、硅基流动和自定义兼容接口，自动填入示例地址和模型，可手工修改。各模型分别保存密钥、独立测试和清除；只配置视觉即可导入，只配置 JD 即可对本地规则导入或已保存的项目执行岗位分析。视觉服务须支持 image_url/data URL 和 JSON 输出，文本模型须支持 JSON 输出。具体模型及接口权限以服务商控制台为准。未联调真实服务，不保证所有示例模型均可用。密钥只保存在本地内存；更换地址不会沿用旧密钥。测试不自动保存。

可通过环境变量启动：

```powershell
$env:OPENAI_API_KEY="你的API密钥"
$env:OPENAI_MODEL="你的JD模型"
$env:RESUME_VISION_MODEL="你的视觉模型"
# $env:RESUME_VISION_API_KEY="独立视觉密钥"
# $env:RESUME_VISION_BASE_URL="独立视觉地址"
# $env:OPENAI_BASE_URL="https://api.openai.com/v1"
python server.py
```

API 与 ChatGPT 订阅独立计费，视觉导入可能比文本分析更贵。选择 AI 导入简历及参考模板时，程序会将每页图像（含照片、联系方式等）和 PDF 原生文字/字号样式发送给你配置的服务，上传前会要求确认；仅编辑、预览、打开已保存项目、保存、HTML 导出及打印不需要 API。JD 分析发送文字与 JD。请勿使用不可信服务；请在上传他人模板前获得授权。

## v0.5：视觉 AI 主导识别

1. 本地渲染 PDF 高清整页图片，同时提取原始文字和字号、字体、颜色、粗体等样式证据（不做段落或同行规则识别）。
2. 视觉模型直接判断阅读顺序、行列关系、独立段落、段内软换行、标题、装饰线、照片区域，返回严格 JSON 行列结构。API 错误或结构无效时直接报错，不回退至旧坐标启发式识别器。支持没有文字层的扫描 PDF，但须校对。
3. 本地把结构转换为可编辑 HTML 文档流；原生 PDF 样式优先，照片从原稿局部渲染裁切，不生成新照片。姓名/求职意向同行；三列中间字段居中、两侧对齐；正文整体居中、段内两端对齐，内容高度随编辑变化。模型判断有误时，仍需人工校对。
4. 对原生文字与 AI 输出进行忽略空白的字符数量核对，提示潜在漏字或新增字；此检查不验证文字顺序及语义，也不能检查扫描件原文。使用左右原稿对照检查后再进行 JD 改写。
5. 可选模板学习也走视觉识别，随后提取模板样式迁移到自己的简历；不会把模板个人信息或图片复制到自己的简历。仍是样式迁移，不支持任意复杂版型完整重构。
6. 保留 v0.4 的编辑、撤销、项目保存、恢复、HTML/PDF 导出及 JD 改写，保护同行元数据不被 JD 模型删除或改写。改写以原始事实库为依据，提供证据和数字检查提示，逐条审核。

## 限制

- 视觉模型可能漏字、错读、错误合并段落或误判照片区域。没有真实模型联调或真实简历视觉测试；自动测试通过 mock 验证结构处理和调用流程，不能证明视觉识别准确率。
- PDF 不保证可同时像素级还原与自由重排；复杂多栏、矢量图形、缺失字体、扫描件中的准确字号及多页跨页重排仍有限制。导出前检查分页与照片。照片使用原稿裁切像素，裁切范围由模型预测。
- PDF 文件最多 20MB、10 页，逐页调用模型，可能耗时。API 不兼容时需更换视觉模型/服务，不静默回退。
- 旧版 JSON 可继续打开，但不会恢复之前丢失的结构。请重新导入原始 PDF。
- 首次识别结果作为原始事实库，若有识别错漏，请勿直接用于 JD 改写；需重新识别或人工核验。不能把模型的文字核对提示当作事实证明。
- v0.4 旧解析器保留在 parser.py 作为样式工具和回归测试用途，从 v0.9 起重新提供为可选的本地规则识别模式。
- 请勿将个人简历、项目 JSON、导出 HTML 或 API 密钥提交到 Git 仓库。

## v0.10：排版调整

左侧导航进入「排版调整」。各滑块独立覆盖识别时的排版参数，未调整项显示「原稿」。左右、上下页边距、正文行距、段落间距、章节间距、个人信息行距与内部间距、个人信息与首章节间距均可实时调整。自 v0.10.1 起，照片不会阻止独立首章节标题上移；横线和正文仍避开照片。可缩小照片或调整其顶部偏移。照片可缩放但不改变图像比例。可恢复单项或全部原稿参数，也可以撤销。排版参数保存在项目 JSON 的 doc.layout 中，已保存的旧项目可直接打开后调整，不需要重新识别。HTML/PDF 导出包含调整后的样式。此功能不调用 API。

正文起始位置仍受照片占位和字体实际字形高度限制；滑块不会强行让内容重叠，也不自动重组跨页内容。

可选浏览器回归检查：安装 `playwright` 并运行 `python -m playwright install chromium`，再运行 `python tests/browser_layout_check.py`。亦可通过 `CHROMIUM_PATH` 环境变量指定已安装 Chromium。测试使用模拟 JSON 和离线接口，不会发送真实简历或消耗 API。

## v0.10.2：正文与个人信息独立控制

首个章节标题恢复为真正的正文块（`.resume-body`），不再移入页眉容器。排版调整分为页面、正文、个人信息和照片四组。原 `headerBody` 参数保持向后兼容，但滑块改名为「正文起始间距（整体移动正文）」并归入正文组。新增 `headerShift` 参数：「个人信息垂直位置（下移为正）」只移动个人信息文字，不改变正文标题或照片的位置；向上不超过页面顶部，向下不允许与正文重叠。个人信息内部行距和段距仍因文字自然流动而可能改变正文起始高度，防止内容重叠。照片独立定位，首标题的全宽横线和后续正文避开照片。旧项目可直接打开，无需重新识别；滑块及相应样式随项目保存和导出。导出的独立 HTML 保留当前排版，若在导出后继续增加页眉或标题文字，仍建议返回工作台调整后重新导出。模拟浏览器回归测试验证了首标题 DOM 归属、个人信息单独上下移动、照片调整不推迟标题、横线避让、项目保存和打印样式。本版未使用用户真实 PDF 测试。

## v0.10.3：首章节标题与横线保持一体

删除 v0.10.2 为避让照片而动态增加首标题 padding-bottom 的逻辑。首章节仍在正文中、标题和原来的全宽横线不再被拉开。照片按可用高度等比缩小并保持右侧锚点；顶部偏移必要时会被限制。照片大小滑块表示期望尺寸上限，实际显示尺寸可能因空间不足而更小。个人信息、正文、照片的原有调整参数及旧项目兼容性保留。无需重新识别 PDF。导出 HTML 保存当前计算后的照片尺寸。
